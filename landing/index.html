How it works

Every event, every session, one signal path.

Ground Control runs a local HTTP server inside the app. Every Claude session fires hooks into it on lifecycle events. The MCP binary closes the loop — agents can read and write the board without leaving their terminal.

▶DEPARTEDAgent is actively working
!HOLDINGWaiting on your input or permission
·STANDBYIdle at the prompt, ready to go
■LANDEDFinished its turn
·DARKSession ended normally
✕NO CONTACTProcess exited unexpectedly
MCP Tools

The departures board is agent-native.

Ground Control exposes five MCP tools so your agents can read and write the task board directly — no humans in the loop, no side-channel scripts.

departures_file
Create a new task on the board with a title and optional notes.
departures_claim
Assign a flight to this terminal and mark it as boarding.
departures_update
Change the status, title, or notes on any flight.
departures_list
Read the full board — see what’s queued, in progress, done.
departures_get
Look up a single flight by number or ID.
Install

Up in 30 seconds.

Requires Xcode command-line tools and the Claude Code CLI. Everything else is included.

BASH 
# clone and run in one go
git clone https://github.com/050177/ground-control
cd ground-control
Scripts/run.sh

# or build a release bundle
Scripts/build-app.sh release
open "build/Ground Control.app"
⌘N Open a new terminal — pick a project folder
⌘B Toggle the departures board
⌘Q Quit and close all sessions

Changelog

What’s shipped.

v0.2.0 July 2026
Memory & Sub-agents
  • Resume sessions — reopen any project and it picks up exactly where you left off, same conversation and everything
  • Recent projects panel — one click from the toolbar, no folder picker every time
  • Sub-agent deployment — click the split button on any terminal, type a task, and a second agent spins up in the same folder with full context of what the first one was doing
  • Restore last session on launch — all your open terminals come back automatically if you quit and reopen
  • Auto-update checker — the app tells you when a new version is available
  • Click a flight row to reopen a closed terminal — if you closed a terminal it shows back up right where it was
  • Terminal slots reuse numbers — close T1, open a new one, it’s T1 again instead of T4
  • HOLDING state sometimes stuck after approving a permission fix
  • Splitting a terminal used to resume the wrong session fix
v0.1.0 July 2026
Foundation
  • First release — native macOS app, no Electron, no browser
  • Terminal grid — open as many Claude sessions as you want, all in one window
  • Live status radar — each terminal shows DEPARTED / HOLDING / LANDED at a glance
  • Departures board — agents file their own task cards via MCP, you watch them move through the board without touching anything
  • Notifications — the app pings you when an agent needs input or finishes
About 050177

Small team.
Real problem.

050177 is a small self-funded team. We build tools to make our own work less chaotic, and occasionally those tools are good enough to share.

Ground Control started as a shell script. Then a cron job. Then a proper app. At some point we realised other people had the same problem — a dozen Claude sessions open, no way to know what any of them were doing without tabbing to each one.

We don’t have investors, a growth team, or a product roadmap spreadsheet. We have a text file of things that annoy us and a habit of building the fix.

We didn’t set out to build a product. We set out to stop losing track of which Claude session was doing what. The departures board came from that — it was just a text file we were manually updating, so we made the agents update it themselves.
— 050177
